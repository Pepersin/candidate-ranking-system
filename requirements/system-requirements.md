# Требования к системе ранжирования кандидатов

> **Статус:** учебная проектная документация (НГТУ, 2025). Ниже описано **планируемое поведение** информационной системы, а не подтверждение того, что все функции уже реализованы и протестированы.
>
> **Источники:** лабораторные работы № 1–3 по дисциплине «Системный анализ» и расчётно-графическая работа по дисциплине «Проектирование информационных систем и технологий». Текст структурирован для портфолио по материалам этих работ.

## 1. Назначение

Система предназначена для автоматизации предварительного анализа резюме и ранжирования кандидатов по профессиональным критериям, связанным с требованиями вакансии. Предполагаемые пользователи — небольшие организации и их HR-специалисты.

**Бизнес-цель учебного проекта:** сократить время предварительного отбора на 20–30% относительно ручного процесса. Это **целевой показатель из проектной работы**, а не доказанный результат измерений.

## 2. Роли пользователей

| Роль | Предусмотренные возможности |
| --- | --- |
| Администратор | Управление учётными записями, ролями, вакансиями, критериями и весами оценки; просмотр журнала действий и сводных отчётов |
| HR-специалист | Загрузка резюме, запуск ранжирования, просмотр и фильтрация результатов, комментарии, статусы откликов, формирование и экспорт отчётов |
| Соискатель | Регистрация, заполнение анкеты / загрузка резюме, отклик на вакансию, просмотр статуса отклика |

## 3. Функциональные требования

| ID | Требование |
| --- | --- |
| FR-01 | Система должна предусматривать вход пользователей и разграничение прав по ролям: администратор, HR-специалист, соискатель. |
| FR-02 | Администратор должен иметь возможность управлять вакансиями, критериями оценки и их весовыми коэффициентами. |
| FR-03 | Соискатель должен иметь возможность заполнить анкету или загрузить резюме и отправить отклик на вакансию. |
| FR-04 | HR-специалист должен иметь возможность загружать резюме кандидатов для дальнейшего анализа. |
| FR-05 | Система должна извлекать и структурировать данные из загруженных резюме для последующей оценки. |
| FR-06 | По запросу HR-специалиста система должна рассчитывать рейтинг соответствия резюме заданным критериям и весам, сортируя кандидатов по результату. |
| FR-07 | HR-специалист должен иметь возможность просматривать список и карточки кандидатов, фильтровать результаты и добавлять комментарии. |
| FR-08 | Должны быть предусмотрены изменение статуса отклика, формирование отчёта по результатам отбора и экспорт результатов. |
| FR-09 | Система должна уведомлять пользователя о неподдерживаемом формате резюме и помечать его как ошибку анализа. |
| FR-10 | При отсутствии части данных о кандидате система должна отмечать резюме как неполное; правила расчёта балла в таком случае требуют дополнительного уточнения. |

## 5. Основной сценарий: ранжирование резюме

**Участник:** HR-специалист.

**Предусловия:** пользователь авторизован; имеется вакансия с критериями оценки; резюме загружены; веса критериев настроены.

1. HR-специалист открывает вакансию и запускает ранжирование.
2. Система получает связанные с вакансией резюме.
3. Для каждого резюме выполняется извлечение и структурирование данных.
4. Система оценивает профессиональные параметры по заданным критериям и весам.
5. Система рассчитывает итоговые баллы и сортирует кандидатов.
6. Результаты сохраняются, а HR-специалист получает ранжированный список и может открыть карточку кандидата.

**Альтернативные ситуации, описанные в лабораторной:** неподдерживаемый формат файла; неполные сведения о кандидате; одинаковый итоговый рейтинг нескольких кандидатов.

## 6. Что требует доработки

- **Модель данных:** в лабораторной № 2 после требований к ранжированию приведены сущности другой предметной области — заселения общежитий. Эта модель **не включена** в документ и должна быть спроектирована отдельно для системы кандидатов.
- **Правила оценки:** нужны точные формулы весов, обработка пропусков и равных баллов, а также примеры расчётов.
- **Критерии отбора:** в исходных материалах встречается возраст как критерий. В публичной версии он **не воспроизведён**; критерии следует дополнительно пересмотреть с точки зрения связи с работой, справедливости и применимых требований законодательства.
- **Проверка реализации:** необходимо отдельно сопоставить требования с исходным кодом, если он будет добавлен, и отметить реализованные и нереализованные пункты.
- **Проверка показателей:** целевые времена отклика, доступность и ускорение подбора требуют измерений, а не только формулировки в документе.
